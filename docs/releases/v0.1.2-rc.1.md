# Mermaid for Google Docs 0.1.2-rc.1

Updated Chrome extension packaging preview, including the merged Dependabot updates and verified artifact transfer. **Native Google Docs canvas blocks remain unsupported. Public marketplace launch is blocked pending native integration and real-document testing.** The package is suitable for loading locally and uploading as a dashboard draft; this release does not submit or publish it to the Chrome Web Store.

## Marketplace upload

Download **google-docs-mermaid-0.1.2-chrome.zip** and upload that ZIP directly to the Chrome Web Store developer dashboard. Do not upload the source ZIP or submission-kit ZIP. The upload ZIP contains `manifest.json` at its root, all executable extension files, icons, project license and original production dependency notices. Its numeric manifest version is `0.1.2`, higher than the previous `0.1.1` package.

## Other attachments

- `google-docs-mermaid-0.1.2-submission-kit.zip`: listing text, privacy disclosures, permission justifications, reviewer instructions, icons, two labeled 1280×800 fixture screenshots, generated manifest, dependency notices, browser report and build fingerprints.
- `google-docs-mermaid-0.1.2-source.zip`: complete tracked source for the release, including build scripts, workflows, tests, documentation and the dependency lockfile.
- `manifest.json`: exact manifest included in the upload ZIP.
- `SHA256SUMS`: verify downloaded assets with `shasum -a 256 -c SHA256SUMS`.

## Changes

- Upgrade TypeScript to 7.0.2, Vitest to 5.0.5, jsdom to 30.1.3 and Playwright to 1.64.0.
- Upgrade checkout/setup-node/upload-artifact to v7, download-artifact to v8 and pnpm/action-setup to v6.
- Pin Node 22.22.2 for reproducible development/release builds; check supported Node 24 and 26 runtimes in CI.
- Keep Node typings compatible with the oldest supported Node 22 runtime.
- Verify artifact upload/download checksums in CI, plus the existing package checks and browser-tested runtime fingerprints.

## Verification and launch gate

The release workflow requires a clean dependency audit, documentation and TypeScript checks, 64 unit tests, 12 built-extension Chromium tests, validated archive contents and exact agreement with browser-tested file fingerprints. Screenshots and browser tests use DOM-backed fixtures. They do not verify native Google Docs support.

Before a supported public launch, implement native canvas extraction and verify preview placement, live edits, collaborator changes, pagination, zoom, undo/reopen behavior and the real toolbar permission flow in an authenticated document. Then refresh store screenshots and listing claims, complete the publisher's privacy/distribution declarations and submit for Chrome Web Store review. See `docs/store/README.md` in the submission kit for the prepared materials and checklist.
