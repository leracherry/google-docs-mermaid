# Chrome Web Store packaging preview 0.1.1-rc.1

This prerelease prepares a complete submission artifact set and fixes dependency advisories. **Public store launch is still blocked: native Google Docs canvas extraction is not implemented.** Rendering and screenshots use explicitly labeled DOM-backed demo fixtures. Do not submit this as a working native Docs integration.

## Download

- `google-docs-mermaid-0.1.1-chrome.zip`: upload-format MV3 extension, with manifest at ZIP root, all runtime resources/icons, project license, dependency inventory and original production dependency notices.
- `google-docs-mermaid-0.1.1-submission-kit.zip`: listing copy, privacy and permission answers, reviewer instructions, privacy policy, icons, two 1280×800 fixture screenshots, exact manifest, dependency notices, browser test report and build provenance.
- `google-docs-mermaid-0.1.1-source.zip`: complete tracked source for this release, including lockfile, tests, build scripts, docs and workflows.
- `manifest.json`: exact manifest from the upload package; Chrome version is `0.1.1` because manifests use numeric versions.
- `SHA256SUMS`: verify all downloaded assets with `shasum -a 256 -c SHA256SUMS`.

To install locally, extract the chrome ZIP, enable Developer mode at `chrome://extensions`, and select **Load unpacked** with the directory containing `manifest.json`.

## Changes and verification

- Resolve five dependency advisories by updating DOMPurify to 3.4.17 and Vitest to 4.1.12.
- Add package validation for MV3, version, required files, permissions, site scope, CSP, icon sizes, local HTML/CSS references, notices, unsafe files and ZIP integrity.
- Verify every upload file matches the browser-tested build by SHA-256 fingerprint.
- Add failing-package regression cases and a built-extension screenshot test. CI and release workflows run frozen installation, security audit, documentation/types/unit checks, production build and browser tests before packaging.
- Include original license texts for the installed production dependency closure, a conservative superset of tree-shaken code.
- Keep site access limited to document URLs and only the static logo exposed on the Docs origin, add homepage/CSP, and state the supported surface in extension metadata.

## Remaining publisher work

Implement and test native Docs integration, including real toolbar grants and collaborator/edit/zoom/pagination behavior. Replace fixture images with verified supported-surface screenshots for launch. Complete developer registration, account/contact requirements, distribution choices and privacy certification in the Chrome Web Store dashboard, then submit for review. GitHub releases do not submit an extension to the store.

Read `docs/store/README.md` in the source or submission kit for the official requirements and all prepared store materials.
